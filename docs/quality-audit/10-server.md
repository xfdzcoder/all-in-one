## 存疑（不入台账）

1. `apps/server/src/mail/routes.ts:105` —— `GET /api/mail/gmail/callback` 无 `preHandler: authGuard`（全库唯一无鉴权的业务写入向路由，grep 实证）。OAuth 回调允许匿名访问本身常见，但**未读实现确认**是否校验 `state`/CSRF 与账号归属；若无，属于「未授权绑定邮箱账号」风险。本轮时间盒内未深挖 mail/* 全部文件，建议 13/14 分区或修复批次补查。
2. `apps/server/src/connector/registry.ts:96-100` —— SSRF 校验（`assertSafeOutboundUrl` 内 DNS 解析）与 `fetch()` 各自解析一次 DNS，存在经典 DNS rebinding TOCTOU。需真实 PoC 才能定级；且多数 connector 传 `allowPrivate: true`（D36/D22 明文授权内网目标），该窗口只对 `custom-api`/`rss` 通道有意义。建议补「解析 IP 与连接 IP 一致性」验证后再定级。
3. `apps/server/src/connector/service.ts:34` 等 `allowPrivate: true` —— 数据源 URL 由登录用户配置、可指向任意内网目标并让服务端代取（内网横向探测面）。这与 D22/D36「服务聚合即内网」的产品决策一致，视为既定设计而非缺陷；若未来多用户化需重新评估。
4. `apps/server/src/connector/service.ts:21-22`（Immich 周新增 `size:1000` 单次全量元数据拉取）—— 实测响应体积/耗时未取样，`maxBytes=1MB` 是否经常截断导致该指标稳定降级无法证实，建议真机观察后再定级。
5. `apps/server/src/config.ts:7-13` —— `normalizeFileUrl` 对 `file://host/path`（含 authority）形态会把 `host/path` 当相对路径 resolve，语义存疑；当前部署未见该写法，未定级。
