## 维护约定

1. **需求变更**：修改 `01-requirements.md`，并在 `02-decisions.md` 追加决策条目（含背景与影响），不得静默改写历史结论。
2. **新决策**：一律追加到 `02-decisions.md`，编号递增；重要选型同步更新 `04-tech-stack.md`。
3. **标记体系**：需求优先级使用【必须】【应该】【暂不考虑】【待确认】；决策状态使用 已决 / 待确认。
4. **待定事项**：任何【待确认】项最终汇入 `06-roadmap.md` 的待定清单，不散落各处。
5. 未经确认不进入下一阶段；文档先行于编码。
